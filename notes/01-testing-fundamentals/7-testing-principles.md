#  7 Software Testing Principles

## Definition

Software testing follows seven fundamental principles that help testers plan, design, and execute effective tests while understanding the limitations of testing. 

---

## Key Points

- Principle 1: Testing Shows the Presence of Defects - Just because you found bugs and fixed it doesnt mean it is now error-free.
- Principle 2: Exhaustive Testing is Impossible - Theres a limit on how much you can test specially when it comes to large combinations.
- Principle 3: Early Testing - Testing should begin as early as possible, starting from the requirements and design phases to detect defects before development progresses.
- Principle 4: Defect Clustering - Some modules tend to contain more defects than others, so testers should focus more effort on those high-risk areas.
- Principle 5: Pesticide Paradox - The same set of test cases will prove ineffective when used too repeatedly just like how pests becomes immune to overued pesticides. 
- Principle 6: Testing is Context-Dependent - Testing tools and methods should be based on what is being tested.
- Principle 7: Absence-of-Errors Fallacy - The system shouldnt just be error-free but rather functional and standard quality as well.

## Real Example

While testing the Expense Diary application, I realized that it was impossible to test every possible input combination (Principle 2). Instead, I focused on common user actions and edge cases such as entering invalid values like NaN.
